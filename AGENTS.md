# Development guidance

- Follow `D:/code/guide.md` for shared AI project layout. This file supplies repository-specific contracts.
- Data presets belong in `config/data/`; training presets belong in `config/train/low_res.yaml` and `config/train/sr.yaml`. Use `model`, `augmentation`, `conditioning`, `loss`, `optim`, `lr_bank`, and `train` only where needed. Keep data paths, phase counts and resolution in data presets; keep batches, augmentation and optimization in training presets.
- Use descriptive configuration keys, `[]` lists, blank lines between related groups and brief comments for ambiguous units or semantics. Resolve selected data files with `src/config/train.load_train_config`; save the effective, embedded data settings with the run. Unknown and obsolete keys are rejected at configuration boundaries; do not add legacy migration paths. New SR settings select their own data and bank guidance, and validate their contract against the frozen LR model.
- Keep training presets focused on experiment choices. Omitted advanced options resolve from `TRAIN_DEFAULTS`/`STAGE_DEFAULTS` in `src/config/defaults.py`, after strict key validation; explicit values always win. Omitted `optim.critic_lr` follows `generator_lr`. Save resolved values so changing defaults cannot alter saved runs. Do not derive independent loss weights, batch counts or physical augmentation assumptions merely because their current values match.
- `src/config/`: `files.py` owns YAML I/O and paths, `defaults.py` advanced defaults, `schema.py` accepted keys, `data.py` data/plane contracts, `train.py` resolved training settings and `generation.py` inference defaults. Import from the owner module; keep package `__init__.py` empty.
- `src/model/`: neural networks and diffusion math; `src/data/`: datasets and augmentation; `src/prepare/`: shared phase conversion and resizing.
- `src/train/`: stage-1 and SR training, losses, EMA and training state; `src/predict/`: generation, extension and super-resolution inference.
- `src/predict/sr/` owns SR inference, extension and memory budgets; `src/predict/tiling/` owns shared tile layout, state, fusion and sampling. Seed isolation belongs in `src/predict/random.py`.
- Keep the web UI in root `frontend/`, HTTP code in `backend/src/` and simulation in `simul/src/`. Their entry points stay within those folders (`backend/run.py`, `simul/run.py`, frontend npm scripts). These project-specific boundaries override the shared guide.
- Simulation generation presets belong in `simul/config.yaml` and `simul/config_height.yaml`; training data presets remain in `config/data/`.
- Server resource limits belong in `backend/config.yaml`; load and validate them per app. Keep uint8 phase bounds in request schemas.
- `src/build/`: assembly; `backend/src/`: HTTP; `src/evaluate/`: measurements; `simul/src/`: simulation; `src/storage.py`: tensor artifact I/O.
- Preserve the public `from src.api import InferenceAPI, PlaneAnchor, create_app` interface. Old configurations and checkpoints are unsupported; require current schemas. Internal imports use their owner modules.
- Keep `src/build/model.py` limited to network construction and `src/build/predict.py` to inference assembly. Public inference imports must not load `src/train/`. Shared diffusion training steps belong in `train/trainer.py`; coarse corruption and SR checkpoint I/O belong in `train/sr.py`; run scheduling and artifacts belong in `train/run/`; `loop.py` owns the shared loop, `low_res.py` and `sr.py` own stage setup, and `bank.py` owns LR bank snapshots. Training batch records belong in `train/batch.py`, and metric records/materialization/logging belong in `train/metrics.py`.
- `data.crop_size` is the original 2D field of view in pixels and `data.lo_res_size` is the LR grid size. `data.hi_res_size` is the SR grid over the same field; derive scale as `hi_res_size / lo_res_size` and reject separately declared scale keys. Fractional scale is allowed for a single refinement block with integral output dimensions; multiple tiles require an integer scale and HR grid, stride and margin aligned to coarse voxels. Do not equate crop size with HR size.
- LR preprocessing is original crop → LR phase fractions; SR real slices are original crop → HR phase fractions. Share phase conversion/resizing through `src/prepare/resize.py`; retain fractional occupancy through training and anchor preparation. Reject legacy `input_size` and `data.scale_factor`. SR source compatibility compares crop/LR sizes, phases and domains, not SR output size.
- Train SR from generated volumes of a frozen LR model and real HR 2D slices. Refresh bank samples on the configured cadence; preserve immutable bank files referenced by checkpoints. Retain fractional coarse channels and pass the realized corruption level to SR (zero at inference). Coarse corruption affects model input only, not the area-average consistency target. Generated LR volumes are conditions, not measured 3D ground truth.
- Keep categorical phase IDs and axis meanings explicit. Resize phase channels rather than averaging numeric IDs.
- Name planes `xy`, `xz`, `yz`. Volumes retain D,H,W = z,y,x; their normal axes are 0, 1, 2 respectively. Raw row/column directions are y/x, z/x, z/y. `src/plane.py` owns these mappings. Reject numeric config/critic names; retain the numeric anchor API.
- `model.critic.plane_groups` explicitly partitions observed planes into shared critics, one model and optimizer per group. Use canonical names such as `xy` and `xz_yz`. Average member-plane losses within groups and average groups in both stages. SR keeps groups separate per domain. Use unversioned artifact-kind tags and current checkpoint schemas only. Do not add legacy compatibility or migration paths, or silently change group membership on resume.
- Keep augmentation policies per plane, independently of critic sharing. `augmentation.planes` uses physical `flip_axes` and `rotate_90`; `data.thickness_axis` forbids reversing or exchanging the thickness direction. Preserve alignment within diffusion-time pairs, connectivity triplets and associated channels; real/fake samples follow the same plane policy. Input orientation must already match the plane convention. Optional conditioning.height_enabled retains loader crop origins and infers per-domain extents from full-thickness side images. Save inferred extents and use source-pixel height_origin consistently in LR, SR and tiled inference; do not invent positions for sections normal to thickness.
- LR counts actual critic updates for regularization and preserves connectivity-triplet order along the thickness normal. Time embedding defaults to index; optional scaled embedding uses 1000*t/num_steps consistently in the generator, critic and inference. R2 defaults off and shares the R1 cadence; SR uses the same timestep-pair adversarial loss, R1/R2 cadence and Trainer as LR, with coarse conditioning and an area-average consistency loss. SR rejects anchors/VF and retains coarse and height in both CFG branches.
- `src/train/step.py` owns finite-loss/gradient checks and optimizer-step diagnostics. Update LR's shared scaler once per iteration, and update EMA only after a successful generator step. `src/train/state.py` owns LR training checkpoints and source hashes; inference weights require their current resolved configuration. LR and SR training must not set fixed seeds or persist/restore RNG state or data order. Keep seed-based reproducibility in prediction only. Replay measured-conditioned LR volumes with their measured planes and geometry; do not run a second reverse chain or present replay as 3D truth. Record resolved configuration and diagnostic metrics with each experiment.
- Use the project `.venv`. Run focused tests first, then `python -m pytest tests -q`; use the configured formatter and Ruff checks.
- Preserve unrelated working-tree changes. Training runs, cached LR banks and generated outputs belong in `run/` and are not committed.
- Keep recorded paper results separate from new experiments; a smoke test does not establish reconstruction quality.

- Exclude visible measured planes from parallel adversarial fake samples. Preserve integer anchor regions through sampling. Critic pyramids use area averaging and average per-level losses. Scheduled structure metrics compare 2D measurements and report finite-volume 3D percolation without claiming target tortuosity.

- SR tile conditioning reads one coarse voxel of interpolation halo, then discards the halo after trilinear upsampling. Height fields use the coarse volume's source-pixel origin and subtract HR context margins consistently; overlapping tiles must assign the same height to the same material.

- LR tiled fusion uses a circular z slab one tile deep; each tile is predicted once per diffusion step. Keep model inputs in the current state and stream finalized regions into the next state. Auto storage checks live CUDA free memory and RAM budgets; probability output conversion must remain bounded by tiles. Memory estimates reserve model workspace but cannot guarantee against allocator OOM.
- Single-block LR labels use device-side argmax before CPU transfer. SR checks a separate memory budget before coarse conversion and HR allocation, including interpolation halo and context margins. Phase conversion fills float32 channels directly. Seeded inference must preserve CPU and unrelated CUDA RNG states, including on exceptions.
- The server rejects concurrent generation with 503 and Retry-After instead of waiting on its lock. Metrics are opt-in and share the generation lock. Stream raw labels in bounded chunks and TIFF through an owned temporary file that is closed/deleted on completion, disconnect or cancellation; handle preparation errors before starting the response.
- SR single-block labels rank on the model device; tiled labels rank in bounded depth slabs after the shared diffusion chain. Budget label output and conversion workspace separately from probabilities. In-place probability conversion is limited to owned inference outputs. Validate phase IDs as int64 before comparing against the phase count.
- SR tiles use LR's shared timestep sampler with one global current state, one latent per timestep, blended clean predictions and one posterior update per voxel. Supply coarse/height tile conditions without anchors or VF; account for two CPU states and circular fusion in SR budgets. Context margins participate in tapered overlap and only the global outer margin is cropped.
- Replay reconciles pseudo-anchor intersections with measurements only for conditioning. Connectivity and transition targets use the original generated replay, never a volume with measured planes pasted into it; measured values remain supervised by anchor loss.
- Reserve a bounded download slot before generation, independently of the GPU generation lock. Return it only after response resources are released, including cancellation and disconnect; reject full capacity with 503 and Retry-After.
- Synthetic `geometry.radius_gradient` supplies positive radius multipliers at the exported z endpoints for both particle phases; simulation padding extends endpoint values. Preserve oriented sections, 3D labels and geometry provenance. KID reports the unbiased polynomial estimator and subset variability alongside FID; never clamp negative scores or interpret correlated sections as independent volumes.

- Keep only numbered manual-check scripts directly in `scripts/`. Shared CLI/display helpers belong in `scripts/common/`, bounded experiment drivers in `scripts/experiments/`, and paper reproduction scripts in `scripts/paper/`. Numbered checks accept a weight file or run directory and save results under `run/checks/` by default; provide weight-only usage examples.

- Tests use isolated settings in `tests/fixtures/`; do not assert experiment-specific values from editable presets in `config/`, `backend/config.yaml` or `simul/`. Keep schema, explicit override and value propagation tests using test-owned inputs.
